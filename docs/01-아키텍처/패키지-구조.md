# 패키지 구조

루트 패키지: `com.sbs.board` (`src/main/java/com/sbs/board`)

**도메인별 수직 분할**이 기본이나, JPA 엔티티는 대부분 `global/entity`에 모여 있다(`Reaction`, `Notification`은 예외).

```
com.sbs.board
├── BoardApplication.java          # @EnableJpaAuditing, @ConfigurationPropertiesScan
│
├── auth/                          # 인증 — [[인증-인가-아키텍처]]
│   ├── AuthController             # /api/auth
│   ├── AuthService                # 회원가입·로그인·토큰 재발급
│   ├── CustomUserDetailService    # UserDetailsService 구현
│   ├── CustomUserDetails          # UserDetails 구현 (getId() 추가)
│   ├── RefreshCookieFactory       # HttpOnly 쿠키 생성/만료
│   ├── RefreshTokenRepository
│   ├── UserRepository
│   ├── TokenPair                  # {token, expireIn}
│   ├── LoginUserId / LoginUserIdResolver   # ⚠️ 비활성 상태
│   ├── dto/                       # LoginRequest, SignupRequest, TokenResponse, UserResponse ...
│   ├── jwt/
│   │   ├── JwtTokenProvider       # 생성·검증·subject(email) 추출
│   │   └── JwtAuthenticationFilter# OncePerRequestFilter
│   ├── oauth/                     # 카카오 "수동" 구현 (레거시)
│   │   ├── KakaoOAuthController   # /api/oauth/kakao
│   │   ├── KakaoOAuthService / KakaoOAuthClient / KakaoOAuthProperties
│   │   └── dto/
│   └── oauth2/                    # Spring Security 표준 OAuth2 (현행)
│       ├── CustomOAuth2AuthorizationRequestRepository  # state를 쿠키에 저장
│       ├── CustomOAuth2UserService                     # 카카오 등 OAuth2
│       ├── CustomOidcUserService                       # 구글 OIDC
│       ├── OAuth2LoginSuccessHandler                   # JWT 발급 + JSON 응답
│       └── OAuth2LoginFailureHandler
│
├── board/                         # 게시판 — [[API-Board]]
│   ├── BoardController / BoardService / BoardRepository
│   └── dto/ BoardRequest, BoardResponse, BoardDTO
│
├── post/                          # 게시글 — [[API-Post]]
│   ├── PostController / PostService / PostRepository
│   ├── PostSecurity               # @Component("postSecurity") 소유권 검사
│   ├── FileStorageService         # [[파일-업로드-아키텍처]]
│   └── dto/ PostRequest, PostDTO, PostImageResponse, PostListResponse
│
├── comment/                       # 댓글 — [[API-Comment]]
│   ├── CommentController / CommentService / CommentRepository
│   ├── CommentSecurity            # @Component("commentSecurity")
│   └── dto/ CommentCreateRequest, CommentResponse(record)
│
├── reaction/                      # 좋아요/싫어요 — [[API-Reaction]]
│   ├── ReactionController / ReactionService
│   ├── PostReaction / PostReactionRepository        # ← 엔티티가 여기에 있음
│   ├── CommentReaction / CommentReactionRepository
│   ├── ReactionType (LIKE, DISLIKE)
│   └── dto/ ReactionRequest(record), ReactionResponse
│
├── notification/                  # 알림 — [[알림-이벤트-아키텍처]]
│   ├── NotificationController / NotificationService / NotificationRepository
│   ├── Notification               # ← 엔티티가 여기에 있음
│   ├── NotificationType (COMMENT_ON_POST, REPLY_ON_COMMENT)
│   ├── CommentCreateEvent (record)
│   ├── NotificationEventListener  # @TransactionalEventListener(AFTER_COMMIT)
│   └── dto/ NotificationResponse
│
├── user/                          # 사용자 프로필 — [[API-User]]
│   ├── UserProfileController / UserProfileService / UserProfileRepository
│   └── dto/ UserProfileResponse
│
└── global/
    ├── IngestResult               # {status, message} 범용 결과 DTO
    ├── config/
    │   ├── SecurityConfig         # 필터체인·권한 URL 매핑
    │   ├── WebConfig              # /images/** 정적 핸들러, Page 직렬화
    │   ├── RestClientConfig       # RestClient Bean
    │   ├── RestAuthenticationEntryPoint  # 401 JSON
    │   └── RestAccessDeniedHandler       # 403 JSON
    ├── entity/                    # Board, Post, PostImage, Comment, User, UserProfile, RefreshToken
    └── exception/                 # [[예외-처리-아키텍처]]
        ├── ErrorCode (enum)  ErrorResponse  GlobalExceptionHandler
        └── BusinessException 계열 (NotFound / Duplicate / Forbidden / Unauthorized / OAuth2DuplicateEmail)
```

## 계층 규약

| 계층 | 책임 | 하지 말아야 할 것 |
|---|---|---|
| `Controller` | HTTP 바인딩, 권한 애노테이션, DTO 반환 | 비즈니스 로직, 엔티티 직접 노출 |
| `Service` | 트랜잭션 경계(`@Transactional`), 도메인 규칙 | `HttpServletRequest` 의존 |
| `Repository` | Spring Data JPA 쿼리 | 로직 |
| `*Security` | `@PreAuthorize` SpEL에서 호출하는 소유권 판정 | 상태 변경 |
| `entity` | 영속 상태 + `toDTO()` 정적 팩토리 | 리포지토리 주입 |

> 엔티티에 `toDTO()` / `toResponse()` 정적 메서드를 두는 패턴이 일관되게 쓰인다.
> 예: `Post.toDTO(post, loginUserId)`, `Comment.toResponse(comment)`, `Notification.toResponse(n)`

## 명명 관례

- 요청 DTO: `XxxRequest` (`SignupRequest`, `PostRequest`, `CommentCreateRequest`)
- 응답 DTO: `XxxResponse` 또는 `XxxDTO` (혼재 — `PostDTO` vs `BoardResponse`)
- 신규 DTO는 `record` 선호 (`CommentResponse`, `ReactionRequest`, `CommentCreateEvent`)
