# 용어집

이 프로젝트에서 특정 의미로 쓰이는 용어들.

## 도메인 용어

| 용어 | 코드상 이름 | 의미 |
|---|---|---|
| 게시판 | `Board` | 게시글을 담는 최상위 분류. ADMIN만 생성 |
| 게시글 | `Post` | 게시판에 속한 글. 이미지 0~5장 첨부 가능 |
| 댓글 | `Comment` (`parent == null`) | 게시글에 직접 달린 최상위 댓글 |
| 대댓글 | `Comment` (`parent != null`) | 댓글에 달린 답글. **여기서 더 깊어질 수 없다** |
| 반응 | `Reaction` | 좋아요(`LIKE`) / 싫어요(`DISLIKE`) |
| 알림 | `Notification` | 댓글 발생 시 생성되는 수신자별 레코드 |
| 프로필 | `UserProfile` | 인증정보(`User`)와 분리된 부가 정보 |

## 인증 용어

| 용어 | 의미 |
|---|---|
| **Access Token** | JWT. 헤더로 전송. 수명 1시간. `subject`는 **email** |
| **Refresh Token** | UUID 문자열(JWT 아님). HttpOnly 쿠키. 수명 10시간. DB에 저장 |
| **재발급 (reissue)** | Refresh Token으로 새 Access Token을 받는 것. `POST /api/auth/reissue` |
| **회전 (rotation)** | 재발급 시 Refresh Token도 새로 발급하는 것. **이 프로젝트에는 없다** |
| `providerId` | 소셜 계정 식별자. `"{PROVIDER}_{고유ID}"` (예: `KAKAO_123456`) |
| `CustomUserDetails` | `User` 엔티티를 감싼 Spring Security 주체. `getId()`로 사용자 ID를 얻는다 |
| `@AuthenticationPrincipal` | 컨트롤러에서 인증 주체를 주입받는 애노테이션 |
| `@PreAuthorize` | 메서드 실행 전 권한 검사. SpEL로 Bean 호출 가능 |
| `postSecurity` / `commentSecurity` | `@PreAuthorize` SpEL에서 소유권을 판정하는 Bean 이름 |

## 상태 / 정책 용어

| 용어 | 의미 |
|---|---|
| **Soft Delete** | 레코드를 남기고 `deleted = true` 플래그만 세움. 댓글에만 적용 |
| **Hard Delete** | 실제 DELETE. 게시글·게시판·반응에 적용 |
| **토글 (반응)** | 같은 타입을 다시 누르면 취소, 다른 타입이면 전환 |
| **소유권 (ownership)** | 작성자 본인 여부. 수정/삭제 권한의 기준 |
| **`canEdit` / `canDelete`** | 응답에 담기는 소유권 힌트. UI 버튼 노출 제어용 |

## 기술 용어

| 용어 | 의미 |
|---|---|
| `ddl-auto: update` | 엔티티 변경을 DB 스키마에 자동 반영. 운영 부적합 |
| `@EntityGraph` | 연관 엔티티를 조인으로 함께 로딩. N+1 방지 |
| `@BatchSize` | 지연 로딩 시 IN 절로 묶어서 조회. N+1 완화 |
| `@TransactionalEventListener(AFTER_COMMIT)` | 트랜잭션 커밋 후 실행되는 이벤트 리스너 |
| `REQUIRES_NEW` | 새 트랜잭션을 시작하는 전파 옵션 |
| `VIA_DTO` | `Page<T>` 직렬화 모드. 응답이 `{content, page:{...}}` 형태 |
| `storedName` | 디스크에 저장된 실제 파일명 (`{uuid32}.{ext}`) |
| `originalName` | 사용자가 업로드한 원본 파일명 |
| `sortOrder` | 이미지 정렬 순서 (0부터, 업로드 순서) |
| `IngestResult` | `{status, message}` 형태의 범용 결과 DTO |
| `ErrorCode` | 상태코드 + 한국어 메시지를 묶은 enum. 에러의 단일 진실 공급원 |

## 문서 표기 규칙

| 기호 | 의미 |
|---|---|
| 🌐 | 인증 불필요 |
| 🔒 | 인증 필요 |
| ✍️ | 작성자 본인만 |
| 👑 | ADMIN 권한 |
| 🍪 | Refresh 쿠키 필요 |
| ✅ | 구현 완료 |
| ⚠️ | 주의 필요 / 부분 구현 |
| ❌ | 미구현 |
| 🚧 | 백엔드 수정이 선행되어야 함 |
| 🔴🟠🟡🟢 | 이슈 심각도 (P0~P3) |

## 자주 헷갈리는 것들

| 헷갈리는 점 | 정답 |
|---|---|
| JWT `subject`가 userId? | **email**이다 |
| `PostDTO.author`가 사용자 ID? | **닉네임 문자열**이다 |
| `PostDTO.board`가 boardId? | **게시판 이름 문자열**이다 |
| `accessToken`에 `"Bearer "`가 있나? | 로그인 응답은 **있고**, reissue 응답은 **없다** |
| 게시글 응답에 좋아요 수가 있나? | 있다. `like`/`disLike`/`myReaction` (댓글은 `likeCount`/`dislikeCount`) |
| 댓글 페이징 `totalElements`가 전체 댓글 수? | **최상위 댓글 수**다 |
| `page.number`가 1부터? | **0부터**다 |
| 삭제 API가 JSON을 반환? | 게시글/게시판 삭제는 **plain text `"ok"`** |
| 반응 경로 철자는? | 게시글은 `reation`(오타), 댓글은 `reaction`(정상) |
| 401이 오면 항상 토큰 문제? | 아니다. 미처리 예외도 401로 위장된다 ([[알려진-이슈]] BE-25) |
| `updated_at`이 수정 시각? | 5개 엔티티는 **생성 시각 고정** ([[알려진-이슈]] BE-14) |
| 엔티티가 전부 `global/entity`에? | `Reaction`, `Notification`은 각자 패키지에 있다 |
